Teoria O que é CRUD? Como funciona?

CRUD é o acrônimo das quatro operações fundamentais de persistência de dados: Create · Read · Update · Delete. Em APIs REST, cada operação usa um método HTTP diferente — experimente cada seção abaixo e observe a requisição e resposta em tempo real.

CreatePOST /pessoas/

Criar registro

Envia dados no corpo (body) em JSON. O servidor valida e persiste.

201 Created
ReadGET /pessoas/

Ler registros

Sem corpo na requisição. O servidor devolve dados. Operação segura e idempotente.

200 OK
UpdatePUT /pessoas/{cpf}

Atualizar registro

Substitui completamente o recurso. Todos os campos devem ser enviados.

200 OK
DeleteDELETE /pessoas/{cpf}

Remover registro

Remove permanentemente. Sem corpo — só o identificador na URL.

200 OK

Create — Criar um novo registro

Método POST · Endpoint /pessoas/
POST Formulário de Criação /pessoas/
📚 Como funciona o CREATE? O método POST envia os dados no corpo (body) da requisição em formato JSON. O servidor valida cada campo e, se tudo estiver correto, persiste no banco e retorna 201 Created. Se o CPF já existir, retorna 409 Conflict.

✨ Observe ao lado como o JSON é montado em tempo real enquanto você preenche!
📤 Requisição HTTP — atualiza conforme você preenche

Read — Consultar registros

Método GET · Endpoints /pessoas/ e /pessoas/{cpf}
GETBuscar por CPF/pessoas/{cpf}
📚 READ por ID — Como funciona? No GET, nunca há corpo na requisição. O identificador (CPF) vai direto na URL como parâmetro de rota. Retorna 200 OK com os dados ou 404 Not Found se o CPF não existir.
GETListar Todos/pessoas/
📚 READ lista — GET sem parâmetro O GET na rota base /pessoas/ devolve todos os registros como um array JSON. Nenhum parâmetro ou corpo — só a URL.
📤 Requisição HTTP
REQUEST
← Digite um CPF ou clique em "Listar Todos"...

Update — Atualizar um registro

Método PUT · Endpoint /pessoas/{cpf}
PUTFormulário de Atualização/pessoas/{cpf}
📚 Como funciona o UPDATE? O PUT faz substituição completa do recurso. O CPF na URL identifica qual registro substituir; o corpo JSON contém os novos valores — todos os campos são obrigatórios.

💡 PATCH (não implementado aqui) atualizaria apenas os campos enviados.
📤 Requisição HTTP — atualiza conforme você preenche

Delete — Remover um registro

Método DELETE · Endpoint /pessoas/{cpf}
DELETEFormulário de Remoção/pessoas/{cpf}
📚 Como funciona o DELETE? O método DELETE remove o recurso permanentemente. Não há corpo na requisição — apenas o CPF na URL identifica o alvo. Retorna 200 OK se removido, ou 404 Not Found se o CPF não existir.

🔒 Em sistemas reais, costuma exigir autenticação e confirmação do usuário.
⚠️ Atenção! Em sistemas reais, um DELETE costuma ser irreversível. Estratégias comuns: soft delete (campo ativo = false) ou tabela de auditoria.
📤 Requisição HTTP — sem corpo (só a URL)
REQUEST
