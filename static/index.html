Teoria O que é CRUD?

CRUD é o acrônimo das quatro operações fundamentais de persistência de dados: Create · Read · Update · Delete. Em APIs REST cada operação mapeia para um método HTTP com semântica bem definida.

Operação Método HTTP Endpoint Status de sucesso O que faz
Create POST POST /pessoas/ 201 Created Envia dados no corpo (JSON) para criar um novo recurso
Read GET GET /pessoas/ · GET /pessoas/{cpf} 200 OK Lê dados sem modificar nada no servidor — idempotente e seguro
Update PUT PUT /pessoas/{cpf} 200 OK Substitui completamente o recurso existente pelo novo corpo
Delete DELETE DELETE /pessoas/{cpf} 200 OK Remove permanentemente o recurso — sem corpo na requisição
Códigos HTTP relevantes: 200 OK 201 Created 400 Bad Request 404 Not Found 409 Conflict 422 Unprocessable Entity 500 Server Error

POST /pessoas/ Criar Pessoa
📚 CREATE — Como funciona? O método POST envia um corpo (body) no formato JSON com os dados da nova pessoa. O servidor valida, persiste e retorna 201 Created. Se o CPF já existir, retorna 409 Conflict. O CPF é validado pelo algoritmo oficial dos dígitos verificadores.
GET /pessoas/{cpf} Buscar Pessoa
📚 READ por ID — Como funciona? O método GET é somente leitura — nunca altera dados. O identificador (CPF) vai diretamente na URL, não no corpo. Retorna 200 OK com os dados ou 404 Not Found se inexistente. Aceita CPF com ou sem formatação.
📚 READ todos — GET sem parâmetro Quando o GET é feito na rota base /pessoas/, o servidor retorna todos os registros em um array JSON. Útil para listar e popular tabelas.
PUT /pessoas/{cpf} Atualizar Pessoa
📚 UPDATE — Como funciona? O PUT substitui completamente um recurso. Todos os campos devem ser enviados mesmo que apenas um mude. O CPF da URL identifica qual recurso atualizar; o CPF do corpo é o novo valor (pode ser igual ou diferente). Diferença para PATCH: PATCH atualiza parcialmente.
DELETE /pessoas/{cpf} Excluir Pessoa
📚 DELETE — Como funciona? O método DELETE remove o recurso permanentemente. Não há corpo na requisição — apenas o CPF na URL identifica o alvo. Retorna 200 OK se removido ou 404 se não encontrado. Em produção, geralmente exige autenticação e autorização.
⚠️ Atenção! Em sistemas reais, um DELETE costuma ser irreversível. Estratégias comuns: exigir confirmação, usar soft delete (campo ativo = false), ou manter histórico em tabela de auditoria.
